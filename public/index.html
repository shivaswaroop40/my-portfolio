Enforcement-readiness of generated Kubernetes NetworkPolicies

Master thesis · Ankra · 2026

Every tool out there can generate a NetworkPolicy that blocks attacks. But can it tell you if the policy is safe to turn on without breaking your app? Turns out, no. The papers don't check either, they evaluate against the same traffic the tool observed. So I built a benchmark that injects real attacks and scores any generator on block-rate, over-privilege and false-denies, plus a prototype that fuses eBPF/Hubble flows with dependencies pulled from cluster config. Watching traffic alone tops out around 72% of the edges an app needs. Adding config gets it to 82% and stops the policies breaking things. All of this measured on a live k3s + Cilium cluster against the Ankra control plane and Sock Shop.

  • eBPF
  • Cilium
  • Hubble
  • Kubernetes
  • NetworkPolicy
  • k3s

CKA Practice: Migrate an Ingress to Gateway API

Challenge · medium

An app served over HTTPS by ingress-nginx has to move to Gateway API with zero downtime: stand up a Gateway and HTTPRoute on staging, verify traffic, flip production over, then retire the Ingress.

  • Kubernetes

Issue Per-Pod mTLS Certificates with PodCertificateRequest

Challenge · medium

Kubernetes 1.37 can hand every pod its own short-lived X.509 identity, no mesh and no sidecar. The API issues nothing without a signer, though, and a request nobody answers waits forever. Get a stalled workload its certificates and make the server enforce mutual TLS.

  • Kubernetes
  • mTLS
  • PKI
  • workload identity

CKA Practice: Renew Expiring Control Plane Certificates

Challenge · medium

kubectl is dead: the kube-apiserver certificate expired and the control plane went with it, while the workload quietly keeps serving. Diagnose the expiry offline, renew, and prove the cluster recovered.

  • Kubernetes
  • kubeadm

  • CKA

CKA Practice: Recover a Broken Static Control-Plane Pod

Challenge · medium

Every kubectl command fails and the usual tools tell you nothing, because the thing that answers them is what broke. Work from the node itself, through crictl and the kubelet, to bring the API server back.

Challenge · easy

A worker node dropped to NotReady and took part of the workload with it. The runtime is fine and the control plane is healthy; the trail leads from kubectl symptoms down into systemd and the kubelet config.
